# Merge Cleanup 상세 절차
Use when: `clean` is requested to synchronize the default branch and clean verified merged-task leftovers.
Required by: `clean`; post-manual-merge local cleanup.
Side effects: local-destructive — verified default-branch fast-forward and safe merged-task local cleanup only; no authored source edits or GitHub mutation
Do not use when: task scope or default identity is unknown, synchronization fails, or conflicting state invalidates the inventory.

`clean` synchronizes the actual default branch before deleting eligible local leftovers. It permits verified Git fast-forward, not authored source edits, GitHub writes, PR merge/auto-merge, or remote branch deletion.

1. **Resolve scope and default.** Inventory the requested PRs, branches, worktrees, and temporary paths with their task links. With no arguments, use only evidence for the current task; never expand to repository-wide candidates. Unknown task scope blocks deletion and `CLEAN_DONE`; it is not a confirmed empty inventory. Match the remote to the target PR's base repository (or the verified task repository for an empty inventory), and identify its default branch from live symbolic HEAD. Never assume `origin`, `main`, or `master`. Stop if repository/default identity is missing or ambiguous, the local default branch is absent, or another worktree has it checked out. Do not create a branch/worktree, move to another worktree, or force a ref to bypass this.

2. **Synchronize safely.** Inspect the current worktree's tracked/index/submodule changes, untracked/ignored files, and in-progress Git operations such as merge/rebase/cherry-pick. Use `git status --porcelain=v1 --untracked-files=all --ignored --ignore-submodules=none` and inspect submodules explicitly; configuration must not hide files or changes. Tracked/index/submodule changes or an in-progress operation block synchronization. Resolve `clean_remote` and `clean_default` only from step 1; never eval command strings. Fetch only the selected default tip:

   ```sh
   git fetch --no-prune --no-prune-tags --no-tags --recurse-submodules=no --refmap= -- "$clean_remote" "refs/heads/$clean_default"
   ```

   Read the successful `FETCH_HEAD` as a commit SHA. The fetch must not update local heads, tags, unrelated refs, or prune. Record the local default's pre-sync SHA and require it to be an ancestor of that fetched SHA before fast-forwarding; ahead/diverged defaults stop here. Any needed switch must use `--no-overwrite-ignore`; fast-forward must use `--ff-only --no-overwrite-ignore --no-autostash`. Preserve nonconflicting untracked/ignored files, including existing `.omo/`. Unsupported options, conflicts, fetch failure, or failed post-sync equality of local default SHA and fetched SHA stop all deletion, including temporary paths. Repository/default failures and conflicting state that invalidates the inventory have the same effect. Never delete files to make synchronization succeed or use reset/rebase to repair it.

3. **Verify each task's merge and current tip.** For every branch, worktree, and temporary-path candidate, require live GitHub `MERGED` evidence for the same task. Connect the PR URL, base/head repositories, head ref, available actual head evidence, and current local tip; do not invent `merged_head_sha`. Branch names and historical merge status alone are insufficient. Require the current tip to be an ancestor of the fetched default tip independently of `git branch -d`'s upstream check. Preserve unmerged, unidentified, post-merge extra-commit, or squash/rebase non-ancestor targets. Keep the requested inventory separate from the eligible deletion list. Preserve the default branch, and never remove the current or primary worktree. Preserve active/locked/shared or ownership-unknown worktrees and their linked branches.

4. **Remove only proven disposable paths.** After the common gates and task merge checks, remove only exact paths proven created by this task, solely owned, and no longer needed. Recheck location, ownership, and use immediately before removal. Preserve tracked, pre-existing, shared, or unknown files, deliverables, reports, verification evidence, handoff material, and session/conductor state. A name, directory, untracked/ignored status, or manifest entry alone is not disposal evidence. Do not follow symlinks or delete their targets. Do not touch paths inside active/locked/shared worktrees. This exact disposal permission is the only exception to Codex's generic ignored/local-only/repo-external PR-representation stop condition; all other stops remain.

5. **Reinspect and remove eligible worktrees, then branches.** After exact disposable cleanup, inspect each candidate's tracked, untracked, ignored, and submodule state with the explicit status options from step 2. Remaining changes or preserved files (including unknown `.env`) preserve both that worktree and its linked branch. Immediately before removal, recheck the tip/ancestry, ownership, activity, lock/sharing, and checkout occupancy. Use ordinary `git worktree remove`, then ordinary `git branch -d`; never delete a branch still checked out anywhere. A task branch left unoccupied after switching to the default can qualify if every other check passes. A refusal preserves the target; never bypass it with `-D`, `--force`, reset, `git clean`, or a recursive sweep. Never delete remote branches.

6. **Report verified outcomes.** Report default-branch before/fetched/after SHAs and deleted, preserved, and stopped targets with reasons. An unsafe requested target blocks `CLEAN_DONE` but does not block an independently safe target once common gates pass. Out-of-scope preservation does not block completion. Emit `CLEAN_DONE` only after verified synchronization and resolution of every requested target; a confirmed empty inventory can complete, unknown scope cannot. Verify actual refs/paths after each deletion rather than treating a command attempt as success.
